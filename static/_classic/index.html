AI Element Assets Optional · split → restore

This whole step can be skipped — you don't have to generate anything. Step 3 will automatically fall back to your step 1 uploads. Generating is useful when you want cleaner assets (no hands, no clutter, no watermarks), consistent lighting, or a restaged scene.
Working from your uploaded product shots, the AI first identifies and splits the individual paper components in the frame (main invitation, RSVP, details, menu, envelope or outer shell, liner, wax seal…), then outputs restored reference assets in the selected mode. Results are added to the library automatically and become the default source for camera-move inputs and AI video first / last frames; your original uploads drop to fallback.
Fidelity limit: AI redrawing does not guarantee character-by-character accuracy on small type (drift has been measured). For text-dense cards (main invitation, RSVP), trust the original photo or the design source file — treat AI output as atmosphere reference, scene reconstruction, and overall composition.

Video Generation Camera moves + AI handheld

Two output tracks load together on this step, and both flow into step 4 composition:
1. Camera moves — 2.5D geometric displacement, zero AI compute, zero text distortion, fixed five-shot sequence.
2. AI segmented handheld — the AI identifies every component in the set and orders them, then generates one clip per component (“pick up → centre → micro-tilt → hold”), stitched in order with a Hero ending. One clip per card gives the highest success rate and text stability.

1 · Camera moves — 2.5D geometric, no AI compute, fixed five-shot sequence

Runs the standard camera-move spec: fixed five-shot sequence, slow / steady / even, hard cuts between shots, rendered and stitched into a single film in one pass. Pure geometric displacement means zero text distortion. Roughly 15–25 seconds of render time per second of footage — about 3–5 minutes for the 12.5 s five-shot sequence.

Advanced: anchor fine-tuning (optional — content-dense areas are auto-detected)

2 · AI segmented handheld — one clip per card (identify → order → generate → Hero)

New pipeline: the AI first identifies the individual components in the set and orders them as main invitation → RSVP → details → menu → other → envelope / shell (script planning layer). Then each component gets its own 4-second clip of “pick up with both hands → centre display → 3°–5° micro-tilt → hold”, trimmed locally to 2.5–3 s, and finally stitched in order with a Hero ending. One product, one core action per generation — text stability and success rate are far higher than a single long instruction. Every other card stays in place in the background and the camera stays locked (CM-10 spec).

Once the clips are done, all segments enter the step 4 stitch pool already ordered by product sequence, ready to compose with BGM. If the identification flags a component as occluded or too low-quality, generate a handheld storyboard for it in the fold-out below, then switch that clip to use the storyboard as reference.
Legacy: generate the whole set from one long instruction (no longer recommended — the long prompt now serves as the planning layer)

This approach asks the model to show every card in a single generation. In practice text drift and truncated motion are common. The long instruction's role has been taken over by “Identify components & order” above; what actually reaches Seedance is the split single-shot instruction. The controls below are kept for comparison experiments.

The current official prompt covers whole-set display: the model first identifies every independent paper component in frame, then works through main invitation → RSVP → details / reception / information → menu → other cards → envelope / shell, picking up each card → displaying it centre frame → returning it, then settling into a tidy final arrangement.
The prompt treats reference image + first frame + last frame as the sole visual authority, so specifying a last frame is strongly recommended (first/last-frame mode). Without it, the ending has no reference. The first frame defaults to step 2's element assets (auto-detected; falls back to step 1 uploads if step 2 produced nothing). If first and last frames differ in aspect ratio, the first frame wins and the last frame is cropped to match.
Spec note: this prompt describes displaying the whole set, card by card, so the first frame should ideally show the complete set in one shot. If step 2 used “per element” granularity, generate an additional whole-set image to use as first / last frame.
